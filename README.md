# WindowMover

複数モニタ環境で、複数のウィンドウをまとめて別のモニタへ移動するための常駐ツール（Windows 10 / 11、x64）。

- `Ctrl + Alt + W` で選択パネルを呼び出す
- ウィンドウ名・プロセス名・ライブサムネイル付きの一覧から、エクスプローラーと同じ操作感（クリック／Ctrl+クリック／Shift+クリック／Ctrl+A）で複数選択
- 移動先モニタをボタンまたは数字キーで指定すると、選択したウィンドウがまとめて移動する
- 「現在の配置を記憶する」で、開いているウィンドウをモニタごとのグループにまとめて記憶し、グループ単位で選択・移動・配置の復元ができる
- 一覧からウィンドウを閉じられる（複数まとめて閉じるときも確認ダイアログあり）
- ウィンドウ単位・グループ単位で位置を記憶し、モニタを再接続したときに自動で元の位置へ戻す

## 1. 必要なもの

| 用途 | ソフト | 入手方法 |
|---|---|---|
| ビルド | .NET 8 SDK | `winget install Microsoft.DotNet.SDK.8` |
| インストーラー作成 | Inno Setup 6 | `winget install JRSoftware.InnoSetup` |

`winget` が使えない場合は、それぞれ公式サイトからインストーラーを入手してください。

## 3. ビルドと動作確認

PowerShell またはコマンドプロンプトで `src` フォルダに移動し、まず開発用に実行して動作を確認します。

```powershell
cd C:\path\to\WindowMover\src
dotnet restore
dotnet run -c Debug
```

起動するとタスクトレイに常駐します。`Ctrl + Alt + W` でパネルが開けば成功です。終了はトレイアイコンの右クリックメニューから。

---

## 4. 単一 exe の publish

配布用に、.NET ランタイム同梱の単一 exe を作ります。

```powershell
cd C:\path\to\WindowMover\src
dotnet publish -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true
```

出力先は次のとおりです。

```
src\bin\Release\net8.0-windows\win-x64\publish\WindowMover.exe
```

---

## 5. インストーラー exe の作成

Inno Setup のコンパイラを使って `installer\WindowMover.iss` をコンパイルします。

```powershell
cd C:\path\to\WindowMover\installer
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" WindowMover.iss
```

GUI で行う場合は `WindowMover.iss` をダブルクリックして Inno Setup Compiler で開き、`Build > Compile` を実行します。

生成物：

```
installer\Output\WindowMoverSetup-3.0.0.exe
```

この exe を実行すると Program Files にインストールされ、スタートメニューと（既定で）スタートアップにショートカットが作成されます。アンインストールは「アプリと機能」から行えます。

### GitHub Actions で作る場合

GitHub でリリースを公開すると、`.github/workflows/release.yml` が Windows 上で単一 exe とインストーラーを作り、そのリリースに `WindowMoverSetup-<バージョン>.exe` を添付します。リリース前に `src\WindowMover.csproj` の `Version` と `installer\WindowMover.iss` の `MyAppVersion` をそろえて更新してください。

## 6. 使い方

1. `Ctrl + Alt + W` を押すとパネルが開く（もう一度押すと閉じる）
   - 起動中にもう一度 WindowMover を起動しても（スタートメニュー・デスクトップ・タスクバーのアイコンなど）パネルが開く。スタートメニューの WindowMover を右クリックして「タスクバーにピン留めする」を選んでおくと、タスクバーからすぐ開ける
2. 移動したいウィンドウのカードをクリックして選択する
   - `Ctrl + クリック`：選択の追加・解除
   - `Shift + クリック`：範囲選択
   - `Ctrl + A`：全選択・全解除
   - 上部の検索ボックスでウィンドウ名・プロセス名による絞り込み
3. 下部の移動先モニタボタンをクリック、または数字キー `1`〜`9` を押す
4. 選択したウィンドウがまとめてそのモニタへ移動する

一覧の表示：
- ウィンドウは、グループごとのまとまり（`▣ グループ名`）と、どのグループにも入っていない「グループ未所属」に分けて表示される。グループのまとまりは最初はたたまれていて、見出しのクリックで展開・たたむ
- 各見出しの「この n 件を選択」で、そのまとまりのウィンドウを一度に選択できる（`Ctrl` を押しながらで追加選択）
- ウィンドウを選択していない状態でモニタボタンをクリック（または数字キーを押す）と、移動ではなく、そのモニタにあるウィンドウを一覧の上にまとめて表示する。そのモニタの「グループ未所属」とグループが分かれて並ぶので、「この n 件を選択」でそのモニタのグループ未所属のウィンドウだけを一度に選べる。もう一度同じモニタをクリックすると元の表示に戻る

その他のキー：`Esc` 閉じる、`F5` 一覧の再取得、`Enter` カーソルのあったモニタへ移動。

### グループ（現在の配置を記憶する）

1. 「現在の配置を記憶する」（`Ctrl + G`）を押すと、いま開いているウィンドウを表示中のモニタごとに1つのグループ（「モニタ1（メイン）」「モニタ2」など）にまとめ、その時点の配置を記憶する。選択状態や検索の絞り込みには関係なく、開いているウィンドウすべてが対象
2. 押すたびに、それまでのグループはすべて置き換えられ、モニタごとにグループが作り直される（手動でグループを作ったり、ウィンドウを追加・除外したりする操作はない。変更した名前は引き継ぐ）
3. 一覧上部のグループ名をクリックすると、そのグループのうち開いているウィンドウが選択され、一覧の先頭に並ぶ（`Ctrl + クリック` で追加選択）。そのまま数字キーやモニタ配置図でまとめて移動できる
4. グループ名をダブルクリックすると、その場で名前を変更できる（Enter で確定、Esc で取り消し）。名前を変更したグループは、次に「現在の配置を記憶する」を押しても、同じモニタのグループにその名前が引き継がれる
5. グループ名を右クリックすると、「このグループを選択」「記憶した配置に戻す」「名前を変更」「削除」ができる

### ウィンドウを閉じる

- カードのタイトル右の `✕` でそのウィンドウを、「選択を閉じる」（`Delete`）で選択中のウィンドウをまとめて閉じる。どちらも確認ダイアログが出る
- 強制終了ではなく、タイトルバーの × を押したのと同じ扱い。未保存の内容があるアプリは、アプリ側で保存の確認が表示される（その場合はパネルが自動で閉じる）

### 位置の記憶

- 選択して「位置を記憶」（`Ctrl + S`）で、ウィンドウごとに今の位置・大きさ・最大化状態を記憶する。「記憶位置に戻す」（`Ctrl + R`）で戻す
- カードの右クリックメニューからも、記憶・復元・記憶の解除・閉じるを操作できる
- 記憶済みのカードには「📌 位置記憶」、グループに属するカードにはグループ名が表示される
- **自動復元**：モニタが再接続されたとき（スリープ復帰で再認識された場合を含む）、そのモニタ上に記憶していたウィンドウを自動で戻す。抜き差ししていないモニタ上のウィンドウは動かさない。トレイメニューの「モニタ再接続時に自動で戻す」でオン／オフできる
- トレイメニューの「記憶した位置にすべて戻す」で、記憶のあるウィンドウを一括で戻せる
- 1つのウィンドウに複数の記憶がある場合（「位置を記憶」と「現在の配置を記憶する」の両方など）は、記憶したモニタがいま接続されているもののうち、最も新しく記憶したものを使う

## 7. 仕様上の注意

- **最大化ウィンドウ**：いったん通常状態に戻してから移動し、移動後に再度最大化します。
- **最小化ウィンドウ**：DWM のライブサムネイルが取得できないため「最小化中」と表示されます。移動すると通常状態に復元されます。
- **拡大率の異なるモニタ間**：移動元の作業領域に対する相対位置・相対サイズを保って配置します。アプリ側が `WM_DPICHANGED` で自身をリサイズするため、移動後に一度だけ位置を補正しています。
- **管理者権限のアプリ**：タスクマネージャーやレジストリエディタなど昇格プロセスのウィンドウは、UIPI により通常権限からは移動できません。移動対象に含めたい場合は `src\app.manifest` の `asInvoker` を `requireAdministrator` に変更して再ビルドしてください。ただし起動のたびに UAC プロンプトが出るため、スタートアップからの自動起動は使えなくなります。その場合はタスクスケジューラに「最上位の特権で実行する」でログオン時タスクとして登録してください。
- **UWP アプリ**：`DWMWA_CLOAKED` により、閉じているように見える不可視ウィンドウは一覧から除外しています。
- **ショートカットが登録できない場合**：他アプリが `Ctrl + Alt + W` を使用しています。`src\App.xaml.cs` の `Native.VK_W` と修飾キーの組み合わせを変更して再ビルドしてください。
- **位置記憶のウィンドウの見分け方**：開いたままのウィンドウはウィンドウハンドルで確実に特定する。アプリや PC を再起動した後は「実行ファイル・ウィンドウクラス・タイトル」で照合する。タイトルが変わるアプリ（ブラウザ、エディタ等）は前方・後方の一致（例：「… - Google Chrome」）で同じウィンドウとみなすため、同じアプリのウィンドウが複数あると取り違えることがある。タイトルがまったく別物になったウィンドウは対象にしない。
- **記憶したモニタが無いとき**：記憶したときと同じ位置・解像度のモニタが接続されていなければ、そのウィンドウは戻さない。
- **保存先**：記憶とグループは `%LOCALAPPDATA%\WindowMover\state.json` に保存される。アンインストールしても残るため、不要なら手動で削除する。
- **AllowsTransparency**：`MainWindow.xaml` で `False` にしています。`True`（レイヤードウィンドウ）にすると DWM サムネイルが一切描画されなくなるため、変更しないでください。
